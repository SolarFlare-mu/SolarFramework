# SpringProxyServerImplV1

`org.solarframework.mu:spring-proxy-server-impl-v1` — the [`ProxyServerAPI`](../ProxyServerAPI/README.md) proxy inside a Spring MVC host: `ProxyController` is a `@RestController` that answers every GET of a domain with its folder's file (`BaseDomain.fileFor`: `index.html` for `/`, no dot segment but `.well-known`), or for an `http` path does a plain GET of the same address from that server — not a forward of method, headers and body — and returns the server's own status and content type (502 if it cannot be reached). `ProxyConfig` sets up HTTPS from `config/certs/ssldomains.p12`. Built the same way as the others (`new ProxyBuilder().registerDomains(...).regenerateCerts().build()`), with no rate limits.

- **The fetch tells the server who called** (`CallerHeaders`, `X-ProxyGuard-Checked: 0`). Until 16 Oct 2026 it carried nothing, so every caller reached the server as this proxy's own loopback address: an allow list holding `localhost` admitted everyone, and all callers shared one limit.
- **Fixed on 16 Oct 2026, found by the C# port:** the controller ran `stripPort` over the domain's *path* (`http://localhost:8080` became `http`, so no fetch ever reached a server, and a folder name lost its case), threw a `NullPointerException` for a host nobody owns (now 404), and answered 404 for anything but a 200 from the server. A `..` segment is still 400, but only a whole segment: `a..b.txt` is a name. A path starting `/_` is still rewritten to `/`; nothing says why.
- `ProxyControllerTest` runs the controller against a real backend on a local port (`com.sun.net.httpserver`); it reads the machine's hosts file but never writes it.

The servlet stack blocks a thread per request; [`SpringProxyServerImplV2`](../SpringProxyServerImplV2/README.md) and [`NettyProxyServerImpl`](../NettyProxyServerImpl/README.md) do not.

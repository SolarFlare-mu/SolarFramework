# SpringProxyServerImplV2

`org.solarframework.mu:spring-proxy-server-impl-v2` — the [`ProxyServerAPI`](../ProxyServerAPI/README.md) proxy on Spring Cloud Gateway (WebFlux). `DomainRegistry` turns each domain into a gateway route and publishes `RefreshRoutesEvent` when they change; `StaticSiteFilter` serves a domain's files (`BaseDomain.fileFor`) with zero-copy writes. Built through `new ProxyBuilder().registerDomains(...).regenerateCerts().build()`, with no rate limits.

The host must be a reactive (WebFlux) application: Spring Cloud Gateway refuses to start on the servlet stack.

- **`CallerHeadersFilter` has the last word on what the backend is told about the caller** (`CallerHeaders`). **The gateway's own `XForwardedHeadersFilter` appends** the socket address to whatever `X-Forwarded-For` the caller sent, and a backend believes the first entry (`IpUtils.callerAddress`); nothing of the gateway's touched `X-ProxyGuard-Checked`, which a backend trusts from loopback. Until 16 Oct 2026 a caller could therefore pass for any address and skip a plugin's allow list and rate limit. The filter is an `HttpHeadersFilter` ordered `LOWEST_PRECEDENCE`: the routing filter applies every header filter as one list sorted by order, the gateway's at 0 and its hop-by-hop one at `LOWEST_PRECEDENCE - 1`, so it runs last — **giving it a lower order puts it before the gateway's, which then append again** (`CallerHeadersFilterTest` pins both the hole and the order).
